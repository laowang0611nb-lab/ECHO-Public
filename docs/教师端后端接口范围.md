# ECHO 教师端后端接口范围

## 范围边界

本清单只覆盖教师 Web 已设计或已明确保留的页面。学生 App 的加入课程、发起对话、发送消息、任务读取与完成等接口不在本文件内，后续单独形成学生端接口需求清单。

后端能力项不强制一一映射成独立 HTTP API。一个页面需要的数据可以由聚合接口一次返回，也可以复用已有领域接口。

## P0 已确认

| 能力 | 接口 | 状态 |
|---|---|---|
| Dashboard 教学总览聚合读取 | `GET /api/v1/dashboard/overview?courseId={courseId}` | 已实现 |
| Course | 现有课程、成员、发布接口 | 保留 |
| Student Analytics / Student Detail | 现有章节分析、知识点分析、学生学习详情和掌握状态接口 | 保留 |
| Knowledge / Resource / PDF | 现有上传、解析、切块、向量化、章节和知识点接口 | 保留 |
| AI Review | 审核列表/筛选/摘要/详情/决策、回答重生成、重生成状态、版本、历史和上下文接口 | P0 已实现 |
| 知识证据闭环 | 掌握趋势、错误聚类、PDF Range/页证据、习题、外部资源、回收站、知识图谱、索引状态、Citation 与学生长期证据 | P0/P1 已实现 |
| Teaching Strategy | 现有教学规则读写接口 | 保留 |
| Server Health | `GET /api/v1/health` | 保留 |
| Demo | 现有运行与健康检查能力 | 保留 |

Dashboard 总览是教师首页的唯一聚合读取入口。后端一次返回统计、近七天趋势、洞察、章节掌握、学习难点和教师行动项，避免前端分别请求课程、学情、知识点和审核数据后自行拼接。

## P1 条件性补充
## 教学策略与执行计划 P0

教师端下一阶段需要完整建立：

```text
教学策略 → 策略详情 → 创建执行计划 → 五步向导 → 发布
→ 执行计划详情 → 任务 / LearningEvent → 效果评估 → 策略效果回流
```

完整字段、路径、枚举和验收标准见：`docs/api/教学策略与执行计划接口需求_v1.md`。

当前 `shared-types`、`api-client` 和运行中的 OpenAPI 尚未提供这组接口。该能力是后续教学行动闭环的 P0 阻断项，前端不得用 Mock、第二套类型或页面内私有 URL 替代。


以下能力只有在对应教师 Web 页面最终保留时才新增，当前不提前实现：

| 能力 | 前置条件 | 建议接口形状 |
|---|---|---|
| 知识库资源编辑 / 重命名 | 知识库页面保留资源重命名操作 | `PATCH /api/v1/documents/{document_id}`，请求体 `{"original_name": "..."}` |
| 执行计划暂停 / 恢复 / 完成 | 执行计划详情页支持状态操作 | `POST /api/v1/execution-plans/{plan_id}/actions`，请求体 `{"action": "pause"}`、`resume` 或 `complete` |

状态操作使用一个动作接口而不是三个独立路径，避免把同一资源的生命周期拆成多个重复端点。

`docs/api/教师端缺失接口需求_v1.md` 中的 PDF 页级证据、知识点趋势与错误聚类、习题、外部资源、回收站、知识关系图、资源索引状态和学生长期证据已经在 `v0.0.80` 落地。
