# ECHO 项目切片

> 快照日期：2026-10-17
> 稳定基线：`main` / `v0.0.255` / commit `5b33b7d`
> 配套文档：[`软件项目流程图.md`](软件项目流程图.md)
> 说明：本文件只描述项目由哪些业务切片组成、每个切片负责什么、切到哪里为止，以及哪些能力适合比赛演示。系统运行过程、数据流和 Mermaid 流程图统一放在《软件项目流程图》中。

## 1. 项目定位

ECHO 是面向高校课程的 AI 教学智能体工程原型。

它不是一个只提供答案的聊天工具，而是连接以下对象的课程教学闭环：

```text
教师 -> 课程和教材 -> 课程知识库
学生 -> 课程 Agent -> 学习行为
学习行为 -> 学习证据 -> 教师分析
教师分析 -> 教学策略 -> 执行计划
执行计划 -> 学习事件 -> 效果回流
```

项目对外最稳定的定位是：

> ECHO 把课程教材、教师规则、学生学习行为和教师干预连接起来，让 AI 在课程边界内提供学习支持，让教师能够看见并干预学习过程。

## 2. 切片原则

### 2.1 按业务闭环切片

每个切片必须具备四类信息：

| 项目 | 要求 |
| --- | --- |
| 输入 | 用户操作、课程对象、教材、学习事件或教师规则 |
| 处理 | 该切片真正负责的业务动作 |
| 输出 | 页面结果、持久化对象或下一环节可消费的数据 |
| 边界 | 哪些事情不在该切片内完成 |

### 2.2 按责任边界切片

项目按以下责任分层：

| 层 | 责任 |
| --- | --- |
| 教师端 | 建设课程、查看学情、审核回答、制定策略和执行计划 |
| 学生端 | 加入课程、学习、提问、查看引用和记录 |
| 后端 | 权限、业务规则、AI 调用、事务、文件和 API |
| 数据层 | 用户、课程、教材、知识、学习、审核和计划持久化 |
| 共享契约 | 类型、API Client、设计 Token |
| Demo 层 | Seed、固定路径、健康检查和现场回退 |

### 2.3 按证据强度切片

| 状态 | 含义 |
| --- | --- |
| 已实现 | 当前代码、接口、页面或模型可以直接证明 |
| 部分实现 | 主链存在，但端到端、稳定性或效果验证不完整 |
| Seed / Demo | 有演示数据或入口，不代表真实教学成效 |
| 后续路线 | 当前不能作为已经完成的能力对外宣称 |

## 4. S01：身份、角色与课程成员

### 4.1 切片目标

为所有业务建立稳定的 `user_id`、角色和 `course_id` 边界。

### 4.2 包含内容

- 教师登录。
- 学生登录。
- 用户角色。
- 课程创建者关系。
- 学生通过课程码加入课程。
- 课程成员读取。
- 课程级权限校验。

### 4.3 输入与输出

| 项目 | 内容 |
| --- | --- |
| 输入 | 登录信息、角色、课程码或课程创建操作 |
| 输出 | User、CourseMember、当前用户、当前课程 |
| 下游消费者 | 教师端、学生端、课程、教材、对话、学情、审核、策略和计划 |

### 4.4 切片边界

- 前端不能自行决定角色权限。
- 后端不能只信任前端传入的 `role`，必须校验课程成员关系。
- 学生端不能调用教师审核、策略和计划写接口。
- 开发认证可以回退 `X-User-Id`，生产环境必须关闭。

### 4.5 主要入口

- `apps/api/app/api/routes/auth.py`
- `apps/api/app/services/auth.py`
- `apps/api/app/services/course.py`
- `database/models/user.py`
- `database/models/course.py`

## 5. S02：课程建设与教学规则

### 5.1 切片目标

让教师建立一门可发布、可学习、可被 AI 使用的高校课程。

### 5.2 包含内容

- 创建课程基本信息。
- 上传教材 PDF。
- 解析教材。
- 生成章节和知识点。
- 设置教学规则。
- 确认发布。
- 课程归档和恢复。

### 5.3 课程创建切片

```text
基本信息
-> 导入教材
-> AI 解析
-> 教学策略
-> 确认发布
```

### 5.4 输入与输出

| 项目 | 内容 |
| --- | --- |
| 输入 | 课程信息、教师规则、PDF 教材 |
| 输出 | Course、Document、Chapter、KnowledgePoint、TeachingPolicy |
| 下游消费者 | 学生端课程、RAG、知识图谱、课程 Agent 和教学分析 |

### 5.5 切片边界

- 课程未发布时，学生不能通过课程码加入。
- 教材解析和结构生成失败不能留下半套结构。
- 归档课程不删除历史数据。
- 当前长耗时步骤仍以串行接口为主，不是完整后台任务队列。

### 5.6 主要入口

- `apps/web/src/features/courses/`
- `apps/api/app/api/routes/courses.py`
- `apps/api/app/api/routes/documents.py`
- `apps/api/app/services/course.py`

- `apps/api/app/services/teaching_policy.py`

## 6. S03：教材证据与 RAG

### 6.1 切片目标

把教师上传的静态教材转换为可检索、可引用、可追溯的课程证据。

### 6.2 包含内容

- PDF 原始文件保存。
- PDF 页文本解析。
- 页文本切分。
- 1024 维 Embedding。
- pgvector 向量检索。
- 回答引用教材 Chunk。
- 引用定位到文档和页码。

### 6.3 输入与输出

| 项目 | 内容 |
| --- | --- |
| 输入 | 课程、PDF、用户问题 |
| 中间数据 | DocumentPage、KnowledgeChunk、Embedding |
| 输出 | 检索结果、课程材料上下文、MessageCitation |
| 下游消费者 | 课程 Agent、教师审核、知识点分析和来源查看 |

### 6.4 切片边界

- 只在当前课程和有效文档范围内检索。
- 没有有效依据时不能伪造 Citation。
- Citation 是实际引用快照，不是装饰性文本。
- 当前稳定演示重点是文本 RAG 和页级来源，不把未完成的视觉检索能力混进来。

### 6.5 主要入口

- `apps/api/app/services/document.py`
- `apps/api/app/services/chunking.py`
- `apps/api/app/services/embedding.py`
- `apps/api/app/services/search.py`
- `apps/web/src/features/knowledge/components/source-viewer-page.tsx`

## 7. S04：知识结构与知识图谱

### 7.1 切片目标

把教材内容转化为教师可管理、学生可浏览、系统可分析的课程知识结构。

### 7.2 包含内容

- 章节生成。
- 知识点生成。
- 章节和知识点编辑。
- 排序、移动、合并和删除。
- 知识点关系保存。
- 教师知识图谱 V2。
- 学生只读图谱嵌入。
- 图谱节点关联掌握度、风险、资源和题目。

### 7.3 核心对象

| 对象 | 说明 |
| --- | --- |
| Chapter | 课程章节 |
| KnowledgePoint | 课程知识点 |
| KnowledgeRelation | 知识点之间的关系 |
| Graph Projection | 将结构和关系投影为图谱 |

### 7.4 关系边界

稳定图谱主要表达：

- `prerequisite`：前置知识关系。
- `related`：相关知识关系。

其他关系文本不能在没有明确语义规则时全部画成同一种强关系。

### 7.5 切片边界

- 图谱节点必须来自真实课程数据。
- 不能为了视觉效果随意新增跨层关系。
- 学生端图谱只读。
- 未提交图谱实验不算稳定能力。

### 7.6 主要入口

- `apps/web/src/features/knowledge/graph-v2/`
- `apps/web/src/features/knowledge/components/knowledge-point-detail-page.tsx`
- `apps/api/app/services/knowledge.py`
- `apps/api/app/services/knowledge_graph.py`
- `apps/api/app/services/knowledge_analytics.py`

## 8. S05：学生 Agent 与多模态学习

### 8.1 切片目标

在学生当前课程上下文中提供受教材和教师规则约束的学习支持。

### 8.2 包含内容

- 加入课程。
- 文本问答。
- 图片输入。
- 音频输入和 ASR。
- 视频输入。
- SSE 流式回答。
- Citation。
- 分层提示。
- Quick Check。
- 标记未解决。

### 8.3 引导式学习切片

```text
学生问题
-> 检索课程依据
-> 判断学习任务
-> 生成回答或分层提示
-> 追问、Quick Check 或继续作答
-> 写入 LearningEvent
```

### 8.4 切片边界

- 回答必须受课程材料和教师规则约束。
- 不适用的知识点不能强行生成 Quick Check。
- 多模态输入不等于论文中的视觉实践资源检索。
- Demo 学习结果不能写成真实班级成效。

### 8.5 主要入口

- `apps/mobile/src/features/chat/`
- `apps/mobile/src/features/learning/`
- `apps/api/app/services/chat.py`
- `apps/api/app/services/quick_checks.py`

## 9. S06：学习事件与掌握度

### 9.1 切片目标

把学生学习行为转换为可追踪、可聚合、可分析的教学证据。

### 9.2 包含内容

- 提问。
- 请求提示。
- Quick Check 正确或错误。
- 重复错误。
- 概念混淆。
- 标记解决。
- 教师人工修正。
- 当前掌握状态。
- 历史掌握快照。

### 9.3 核心对象

| 对象 | 职责 |
| --- | --- |
| LearningEvent | 保存发生过什么 |
| StudentKnowledgeState | 保存当前掌握状态 |
| MasterySnapshot | 保存历史时间点 |

### 9.4 切片边界

- LearningEvent 是行为事实，不是心理结论。
- 掌握度来自可解释事件规则。
- 数据不足时要显示证据不足。
- 趋势可以说明变化，不能自动证明因果关系。

### 9.5 主要入口

- `apps/api/app/services/learning.py`
- `apps/api/app/services/dashboard.py`
- `apps/api/app/services/dashboard_details.py`
- `database/models/learning.py`

## 10. S07：教师学情与证据下钻

### 10.1 切片目标

让教师从课程结果一路看到具体学生、原始对话和教材证据。

### 10.2 包含内容

- 课程总览。
- 章节分析。
- 知识点分析。
- 学生学情。
- 掌握趋势。
- 错误模式。
- 高风险知识点。
- 完整对话。
- Citation 和 PDF 页码。

### 10.3 下钻切片

```text
课程
-> 章节
-> 知识点
-> 学生
-> LearningEvent
-> 原始对话
-> MessageCitation
-> PDF 页面与原文
```

### 10.4 切片边界

- 教师只能看自己课程范围内的数据。
- 页面指标必须有数据口径。
- AI 分析不能替代原始证据。
- 不把相关性写成因果结论。

### 10.5 主要入口

## 11. S08：AI 回答审核

### 11.1 切片目标

在 AI 回答进入正式教学判断前，为教师提供可审核、可修改、可追溯的人工控制点。

### 11.2 包含内容

- 自动风险标记。
- 审核驾驶舱。
- 审核工作台。
- 学生问题上下文。
- 当前回答和教材引用。
- 审核备注。
- 教师修改稿。
- 重新生成。
- 回答版本。
- 审核历史。

### 11.3 审核状态

| 状态 | 说明 |
| --- | --- |
| `open` | 待教师首次审核 |
| `generating` | 正在重新生成 |
| `pending_rereview` | 新版本等待再次审核 |
| `regeneration_failed` | 重新生成失败 |
| `confirmed_correct` | 教师确认正确 |
| `marked_incorrect` | 教师标记错误 |
| `dismissed` | 教师忽略风险 |

### 11.4 切片边界

- 自动审核是提示，不是自动裁判。
- 新回答版本不覆盖原回答。
- 教师修改、确认、忽略和重新生成都要留痕。
- 教师自己的会话不进入学生问题审核。

### 11.5 主要入口

- `apps/web/src/features/ai-review/`
- `apps/api/app/services/review.py`
- `apps/api/app/services/review_workflow.py`
- `database/models/review.py`

## 12. S09：洞察、策略与执行计划

### 12.1 切片目标

把教师看见的学习问题转化为有证据、有教师决策、可执行、可评估的教学行动。

### 12.2 包含内容

- AI 二次分析。
- 分析阶段进度。
- 问题、原因、影响范围和教学建议。
- 教学策略建议。
- 教师采纳、编辑、暂停和完成。
- 执行计划。
- 周计划。
- PlanTask。
- 计划关联 LearningEvent。
- 计划和策略效果评估。

### 12.3 教学行动切片

```text
学习证据
-> AI 教学洞察
-> TeachingStrategy(suggested)
-> 教师采纳或修改
-> ExecutionPlan(draft)
-> 生成周计划和任务
-> 教师发布
-> 学生执行
-> LearningEvent
-> 效果评估
```

### 12.4 教师控制边界

| 对象 | AI 可做 | 教师必须做 |
| --- | --- | --- |
| 分析 | 汇总证据、生成解释 | 判断事实和教学价值 |
| 策略 | 生成建议草稿 | 采纳、修改、暂停、完成 |
| 计划 | 生成计划和任务草案 | 编辑、发布、暂停、继续、完成 |
| 效果 | 聚合前后事实 | 判断是否用于后续教学改进 |

### 12.5 主要入口

- `apps/web/src/features/ai-insights/`
- `apps/web/src/features/teaching-strategies/`
- `apps/web/src/features/execution-plans/`
- `apps/api/app/services/analysis*.py`
- `apps/api/app/services/teaching_strategy.py`
- `apps/api/app/services/execution_plan.py`

## 20. 最终结论

ECHO 最适合拆成十个工程切片：

```text
身份与课程
-> 建课与教材
-> RAG 与引用
-> 知识结构与图谱
-> 学生 Agent 学习
-> 学习事件与掌握度
-> 教师学情分析
-> AI 回答审核
-> 策略与执行计划
-> Demo 与验收保障
```

最终对外口径：

> AI 不替代教师决策，而是把课程知识和学习证据转化为教师可审核、可执行、可追踪的教学行动。
