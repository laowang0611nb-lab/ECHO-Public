# ECHO 后端运行逻辑

## 1. 文档定位

本文描述 `<repo>\apps\api` 当前后端的运行时结构、请求处理链路、核心业务数据流、事务边界和外部依赖。

- 代码位置：`apps/api` 与仓库级 `database/`
- 后端框架：FastAPI + Pydantic + SQLAlchemy Async + Alembic
- 生产数据库目标：PostgreSQL + pgvector
- 测试数据库：aiosqlite
- 后端包版本：`0.0.76`
- 仓库文档版本：`v0.0.76`

本文只描述当前实现，不替代 `docs/API契约.md` 中的接口字段冻结契约。

## 2. 总体架构

后端是一个按请求创建数据库会话的 ASGI 应用。路由层负责协议和权限错误映射，服务层负责业务规则和事务，模型层负责持久化结构，Provider 负责调用外部模型服务。

```text
教师端 / 学生端 / 其他客户端
              |
              v
        FastAPI 路由层
              |
              v
         Service 业务层
        /       |       \
       v        v        v
 SQLAlchemy   Provider   本地 PDF 存储
       |        |
       v        v
 PostgreSQL/  Qwen 兼容 API
 SQLite      Chat / Embedding / LLM
```

主要目录职责：

| 路径 | 职责 |
|---|---|
| `app/main.py` | 创建 FastAPI 应用、注册 CORS、挂载 API Router、管理生命周期 |
| `app/api/dependencies.py` | 数据库会话、当前用户、存储和模型 Provider 依赖注入 |
| `app/api/routes/` | HTTP/SSE 路由、请求参数校验和领域异常到 HTTP 状态码的转换 |
| `app/services/` | 业务规则、查询组合、事务提交和外部服务编排 |
| `database/models/` | SQLAlchemy ORM 模型、关系、唯一约束和检查约束 |
| `app/schemas/` | Pydantic 请求、响应和校验规则 |
| `database/alembic/` | 数据库迁移脚本 |
| `database/seeds/` | 可独立执行的维护或演示数据脚本 |

## 3. 启动与配置

### 3.1 应用创建

`app/main.py` 中的 `create_app()` 会完成以下工作：

1. 读取 `Settings`。
2. 创建 FastAPI 实例。
3. 将 OpenAPI 文档挂到 `ECHO_API_V1_PREFIX` 下，默认是 `/api/v1`。
4. 注册 CORS 中间件。
5. 将所有业务 Router 挂载到统一 API 前缀。
6. 在应用生命周期结束时释放数据库 Engine。

开发时可以使用：

```powershell
cd <repo>
pnpm dev:api
```

或者：

```powershell
cd <repo>
apps\api\.venv\Scripts\python -m uvicorn app.main:app --app-dir apps/api --host 0.0.0.0 --reload
```

### 3.2 配置来源

配置由 `pydantic-settings` 读取，环境变量统一使用 `ECHO_` 前缀，默认环境文件为 `apps/api/.env`。关键配置包括：

| 配置 | 当前用途 |
|---|---|
| `ECHO_DATABASE_URL` | SQLAlchemy Async 数据库连接 |
| `ECHO_DOCUMENT_STORAGE_ROOT` | PDF 本地存储根目录，默认 `tmp/uploads` |
| `ECHO_DEVELOPMENT_AUTH_ENABLED` | 是否允许开发认证和 `X-User-Id` |
| `ECHO_BUSINESS_TIMEZONE` | Dashboard 业务日期分桶时区 |
| `ECHO_LLM_*` | 知识结构生成模型配置 |
| `ECHO_CHAT_*` | 流式聊天模型配置 |
| `ECHO_EMBEDDING_*` | Embedding 模型、维度和批次配置 |
| `ECHO_CHUNK_SIZE_CHARS` | 文档切块字符长度 |
| `ECHO_CHUNK_OVERLAP_CHARS` | 文档切块重叠字符数 |
| `ECHO_RETRIEVAL_MAX_DISTANCE` | 向量检索最大距离阈值 |

知识结构生成的输入预算为：

```text
llm_max_input_tokens = llm_context_window_tokens * llm_context_safety_ratio
```

默认值是 `1,000,000 * 0.7 = 700,000` Token。

### 3.3 数据库连接

`database/db/session.py` 创建全局 Engine 和 `async_sessionmaker`。每个请求通过 `get_db_session()` 获得一个独立的 `AsyncSession`，请求结束后关闭会话。

启动应用本身不会主动执行迁移，也不会强制建立 PostgreSQL 连接。生产数据库需要先执行：

```powershell
cd <repo>
apps\api\.venv\Scripts\python -m alembic -c database/alembic.ini upgrade head
```

## 4. 单次请求的生命周期

普通 HTTP 请求的处理顺序如下：

1. Uvicorn 接收请求。
2. FastAPI 执行 CORS 和路径路由匹配。
3. FastAPI 校验路径参数、查询参数和请求体。
4. `DBSession` 依赖创建请求级数据库会话。
5. 需要认证的路由解析 `CurrentUser`。
6. 路由调用 Service 函数。
7. Service 完成权限检查、查询、写入、提交或回滚。
8. 路由将 ORM 对象交给 Pydantic 响应模型序列化。
9. 请求会话关闭，返回 HTTP 响应。

### 4.1 开发认证

当前 `CurrentUser` 只支持开发身份头：

```http
X-User-Id: <user-uuid>
```

`get_current_user()` 的行为是：

- 如果 `development_auth_enabled` 为 `false`，直接返回 `401`。
- 如果请求头缺失、为空或不是 UUID，返回 `401`。
- 如果数据库中找不到该用户，返回 `401`。
- 找到用户后，将 ORM `User` 注入路由。

生产环境启动时会拒绝开启开发认证。`database/` 已包含 Argon2id 密码凭证、Access JWT、Refresh Session、Profile 和三类新增 migration，但 HTTP 运行时仍没有 Bearer 登录接口；正式认证切换必须在 Web、Android 和测试准备完成后进行。

### 4.2 权限检查

权限主要按以下顺序判断：

1. 课程是否存在。
2. 当前用户是否为该课程成员。
3. 当前用户的课程成员角色是否为 `teacher` 或 `student`。
4. 资源是否属于目标课程或目标学生。

通用异常映射为：

| 状态码 | 典型场景 |
|---|---|
| `401` | 开发认证头缺失、格式错误或用户不存在 |
| `403` | 非课程成员、学生访问教师接口、教师越权加入课程 |
| `404` | 课程、文档、会话、知识点或审核项不存在 |
| `409` | 文档未 ready、重复加入冲突、知识结构冲突、并发更新冲突 |
| `413` | PDF 超过上传限制 |
| `415` | 非 PDF 文件 |
| `422` | 请求体校验失败、不可分割的超限文档、空生成结构 |
| `502` | LLM、Chat 或 Embedding Provider 调用失败 |
| `503` | 模型 API Key 未配置 |

## 5. 持久化模型与关系

### 5.1 身份与课程

- `User`：教师或学生账号。
- `UserCredential`：一对一 Argon2id 密码凭证。
- `AuthSession`：Refresh Token Hash、设备信息、过期和撤销状态。
- `TeacherProfile`、`StudentProfile`：可选的一对一用户档案。
- `Course`：课程元数据、课程码、草稿或发布状态。
- `CourseMember`：课程中的教师或学生身份。课程创建者会自动加入课程。
- `CourseInvite`：邀请生命周期、最大使用次数、使用次数和过期时间。

主要约束：

- 用户邮箱唯一。
- 课程码唯一。
- `(course_id, user_id)` 在 `CourseMember` 中唯一。

### 5.2 教材与解析

- `Document`：上传文件元数据、存储键、大小、页数和 `uploaded/parsing/ready/failed` 状态。
- `DocumentPage`：解析后的页级文本和字符数。
- 本地存储实现位于 `LocalDocumentStorage`，默认写入 `tmp/uploads`。
- `(document_id, page_number)` 唯一。

### 5.3 知识结构

- `Chapter`：属于某份教材的章节，保存标题、摘要和章节顺序。
- `KnowledgePoint`：属于章节的知识点，保存名称、描述和章节内顺序。
- `KnowledgeRelation`：知识点之间的关系边。
- `(document_id, order_index)` 在章节中唯一。
- `(chapter_id, name)` 在知识点中唯一。
- 关系边禁止自环，`(source, target, relation_type)` 唯一。

### 5.4 知识块与检索

- `KnowledgeChunk`：从解析页面切出的可检索文本块。
- 保存课程、教材、章节、全局块序号、页码范围和原始字符数。
- `(document_id, chunk_index)` 唯一。
- `embedding` 使用 1024 维 pgvector 向量。

### 5.5 会话与引用

- `Conversation`：课程范围、用户范围的多轮会话。
- `Message`：用户、助手或系统消息。
- `MessageCitation`：助手回答实际使用的来源快照，保存引用编号、chunk、文档、页码和引用文本。

引用编号是回答中的来源序号，不会被历史接口重新编号。

### 5.6 教学与学习数据

- `TeachingPolicy`：每个课程最多一条自然语言教学规则。
- `LearningEvent`：可解释的学习事件，支持提问、提示、答对、答错、概念混淆、重复错误、解决和教师调整。
- `StudentKnowledgeState`：学生、课程、知识点的当前掌握分，范围 `0-100`。
- `MasterySnapshot`：与学习事件关联的历史掌握度快照。
- `(course_id, user_id, knowledge_point_id)` 在学生知识点状态中唯一。

### 5.7 AI 审核

- `AIReviewFlag`：保存待审核回答的原因、严重级别、状态、详情和教师处理结果。
- 当前审核原因包括缺少课程依据、课程外内容偏重、重复追问、学生标记未解决和教师规则违规。
- `ReviewAnswerVersion`：原回答、重新生成回答和教师修改稿的不可覆盖版本记录。
- `ReviewRegenerationRun`：每次重新生成的状态、进度、指令、失败原因和版本目标。
- `ReviewHistoryEntry`：教师决定和重新生成的有序审计历史。
- `(message_id, reason)` 唯一，防止同一消息因同一原因重复建标记。

## 6. 核心业务链路

### 6.1 认证和课程管理

#### 开发登录

`POST /api/v1/auth/login`：

1. 检查开发认证开关。
2. 按邮箱查找用户。
3. 已存在时校验请求角色与现有角色一致。
4. 不存在时创建用户。
5. 唯一冲突时回滚并重新查询用户，处理并发首次登录。

#### 创建课程

`POST /api/v1/courses`：

1. 只允许全局角色为教师的用户。
2. 生成 8 位课程码。
3. 创建 `Course`。
4. 自动创建创建者对应的教师 `CourseMember`。
5. 默认课程状态为 `draft`。

#### 加入课程

`POST /api/v1/courses/join`：

1. 只允许学生角色。
2. 按课程码查找课程。
3. 课程必须是 `published`。
4. 查询是否已有成员记录。
5. 已存在则幂等返回。
6. 不存在则创建学生成员记录，若并发唯一冲突则回滚后重新查询。

#### 发布和成员

- 只有课程教师可以发布课程。
- 学生必须等课程发布后才能加入。
- 成员列表只向课程教师开放。

### 6.2 教材上传、解析和切块

#### 上传

`POST /api/v1/courses/{course_id}/documents`：

1. 校验课程存在和教师身份。
2. 校验文件扩展名和 MIME 类型。
3. 将文件流写入本地存储临时文件，超过 `ECHO_MAX_UPLOAD_BYTES` 时中止。
4. 写入 `Document` 元数据。
5. 数据库提交失败时删除已保存文件。

#### 解析

`POST /api/v1/documents/{document_id}/parse`：

1. 锁定 `Document` 行。
2. 校验教师身份。
3. 如果文件不存在，标记 `failed`。
4. 将状态改为 `parsing`，删除旧知识块。
5. 在线程池中调用 `pypdf` 提取页文本。
6. 删除旧页记录，写入新的 `DocumentPage`。
7. 更新页数和状态 `ready`，提交事务。
8. 解析异常时状态变为 `failed`，路由返回 `422`。

#### 分块

`POST /api/v1/documents/{document_id}/chunks`：

1. 锁定 `Document` 行。
2. 校验教师身份和 `ready` 状态。
3. 按页读取解析文本。
4. 将连续空白归一化。
5. 按 `chunk_size_chars` 切块，并保留 `chunk_overlap_chars` 重叠。
6. 每个块记录页码范围和字符数。
7. 先删除该教材旧块，再批量写入新块并提交。

### 6.3 Embedding 与课程检索

#### 生成向量

`POST /api/v1/documents/{document_id}/embeddings`：

1. 校验教材处于 `ready` 状态。
2. 读取该教材全部知识块。
3. 校验教师身份。
4. 按批次调用 Qwen 兼容 Embedding API。
5. 校验返回向量数量和维度，当前维度必须为 `1024`。
6. 将向量写回 `KnowledgeChunk.embedding`。

#### 检索

`POST /api/v1/courses/{course_id}/search`：

1. 校验请求者是课程成员。
2. 对查询文本生成查询向量。
3. PostgreSQL 使用 pgvector cosine distance。
4. SQLite 环境使用内存 cosine 排序，保持开发和测试行为一致。
5. 只保留 `ready` 教材且已有 embedding 的块。
6. 按距离阈值过滤并按距离升序返回。

### 6.4 知识结构生成和编辑

#### 自动生成

`POST /api/v1/documents/{document_id}/generate-structure`：

1. 校验文档、课程教师和 `ready` 状态。
2. 读取所有页文本。
3. 调用 `QwenKnowledgeStructureProvider.generate()`。
4. 请求内容小于输入预算时，一次请求生成完整结构。
5. 超过预算时，先按页和字符边界切分材料，再分段抽取章节草稿。
6. 多个草稿按章节和知识点递归合并。
7. 将生成结果替换写入 `Chapter`、`KnowledgePoint`。
8. 对同标题、同名称的现有结构尽量复用，保留关联的学习状态和历史证据。

生成结构使用严格 JSON 解析，并校验章节标题、知识点名称和描述长度。LLM 返回格式不正确时，路由返回 `502`。

#### 手工编辑

教师可以：

- 创建、修改、删除章节。
- 创建、修改、删除知识点。
- 调整章节和知识点顺序。
- 在章节之间移动知识点。
- 合并课程内知识点。

编辑接口都会在服务层重新校验教师成员身份。章节和章节内顺序更新时会先临时偏移顺序值，再写入目标顺序，以降低顺序唯一约束冲突。

#### 合并知识点

合并时服务会：

1. 校验目标和全部来源属于同一课程。
2. 迁移来源关联的学习事件和掌握快照。
3. 重连知识关系，去掉自环和重复边。
4. 按学生聚合目标状态和来源状态，计算平均掌握分。
5. 为受影响学生写入新的掌握快照。
6. 删除来源知识点并重排目标章节。

### 6.5 教学策略

`GET /api/v1/courses/{course_id}/teaching-policy`：

- 课程成员可读。

`PUT /api/v1/courses/{course_id}/teaching-policy`：

1. 校验课程教师身份。
2. 查询当前策略。
3. 存在则更新，不存在则创建。
4. 使用行锁和有限重试处理并发首次创建。
5. 后续聊天会把策略注入 System Prompt。

### 6.6 聊天、RAG 和 SSE

#### 会话

- 课程成员可以创建和列出自己的课程会话。
- 会话的所有者只能读取自己的消息。
- 教师可以通过教师专用接口读取指定学生的会话列表和完整消息。

#### 流式回答

`POST /api/v1/conversations/{conversation_id}/messages/stream` 的流程是：

1. 校验会话存在且请求者是会话所有者。
2. 使用问题向量检索课程知识块。
3. 从数据库读取教学策略和最近历史消息。
4. 先保存学生用户消息，并更新会话标题和更新时间。
5. 如果当前用户是学生，写入 `question_asked` 学习事件。
6. 构造提示词：
   - System Prompt 包含教学规则和引用要求。
   - 课程材料被标记为不可信数据，不能作为指令执行。
   - 附加最近历史消息。
   - 最后附加当前问题。
7. 调用 Chat Provider 流式生成文本。
8. 通过 SSE 发送 `text_delta`。
9. 生成结束后保存助手消息。
10. 解析回答中的 `[n]` 引用，只保存实际引用的来源，并写入 `MessageCitation`。
11. 如果是学生会话，根据引用情况、回答标记和历史问题生成自动审核标记。
12. 发送 `citation` 事件和 `done` 事件。

SSE 事件类型：

| 事件 | 含义 |
|---|---|
| `text_delta` | 增量文本 |
| `citation` | 回答实际使用的来源 |
| `error` | 流式处理中的错误 |
| `done` | 会话和助手消息写入完成 |

注意：流式回答会先提交学生消息，再调用模型。模型调用失败时，学生消息可能已经持久化，但助手消息不会写入。

### 6.7 教师读取学生完整对话

教师专用链路包括：

- `GET /api/v1/courses/{course_id}/students/{student_id}/conversations`
- `GET /api/v1/courses/{course_id}/conversations/{conversation_id}/messages`

服务层会：

1. 检查课程教师身份。
2. 检查学生会话所有者仍是课程学生成员。
3. 按时间读取消息和引用。
4. 从 `LearningEvent.message_id` 推导消息关联的知识点。
5. 对助手消息继承最近一条学生问题关联的知识点。
6. 聚合每个消息的审核状态。
7. 返回 `knowledgePointIds`、`citations` 和 `reviewStatus`。

### 6.8 学习事件和掌握度

`POST /api/v1/courses/{course_id}/learning-events`：

1. 校验课程教师身份。
2. 校验目标学生是该课程学生成员。
3. 校验会话、消息、知识点引用属于该学生和课程。
4. 写入不可变的 `LearningEvent`。
5. 锁定学生的知识点状态行。
6. 状态不存在时创建初始分 `50`。
7. 根据事件类型和权重更新分数。
8. 分数限制在 `0-100`。
9. 写入 `MasterySnapshot`。
10. 并发唯一冲突时回滚并有限重试。

学生聊天产生的 `question_asked` 事件会走同一套写入服务。

查询接口：

- 学生可以查询自己的掌握状态。
- 课程教师可以查询课程内学生的掌握状态。

### 6.9 AI 回答审核

自动标记逻辑只在课程存在可检索教材时启用。当前判断包括：

- 实质问题没有使用任何课程来源。
- 回答出现多个课程外补充标记，或没有引用时出现课程外标记。
- 学生在已有助手回答后重复提问，或明确表示没有解决。
- 学生主动调用未解决上报接口。

教师审核流程：

1. 读取待审核队列。
2. 查看问题、回答、引用、原因和严重级别。
3. 选择确认正确、标记错误或忽略。
4. 保存教师备注和修正答案。
5. 可使用教师指令重新生成回答，原 Message 永远不被覆盖。
6. 原回答、重新生成回答和教师修改稿分别保存为 `ReviewAnswerVersion`。
7. 每次决定和重生成写入 `ReviewHistoryEntry`，并提供状态、版本和上下文查询接口。

### 6.10 教师 Dashboard 和下钻

Dashboard 聚合接口会统计：

- 学生总数。
- 近七天活跃学生数。
- 近七天提问数。
- 学习事件总数。
- 平均掌握度。
- 待审核回答数。
- 高风险知识点。

教师首页总览额外返回：

- 七天趋势。
- 风险等级和摘要。
- 章节掌握情况。
- 学习难点。
- 建议的教师行动项。

趋势按 `ECHO_BUSINESS_TIMEZONE` 的业务日期分桶，默认使用 `Asia/Shanghai`。

下钻接口提供：

- 章节平均掌握度和活跃学习者数量。
- 知识点班级分布和低于 60 分学生数量。
- 学生最近的 LearningEvent、掌握状态和证据。

## 7. 事务、并发和一致性

### 7.1 事务边界

- Service 函数负责调用 `commit()`。
- 业务失败时由 Service 或路由边界回滚。
- 请求级会话关闭时会清理未完成事务。
- 会话、消息、引用、知识结构和学习状态不是单一全局事务。

聊天链路会分段提交：

1. 用户消息和课程会话更新。
2. 学习事件。
3. 助手消息和引用。

因此模型调用失败时，前端可能看到已保存的用户消息，但看不到助手消息。

### 7.2 当前并发控制

已实现的主要保护包括：

- 文档解析和分块使用文档行锁，避免重复解析或重复切块。
- 学习事件更新学生状态时使用行锁和有限重试。
- 教学策略更新使用行锁和有限重试。
- 课程加入、认证注册和多个创建路径使用唯一约束冲突后的回滚或重试。
- 知识结构替换、知识点创建和合并捕获数据库唯一冲突并转换为业务冲突。

知识结构编辑中的章节创建、章节排序和知识点排序仍主要依赖数据库唯一约束和单请求顺序逻辑，不保证所有并发编辑都会自动合并或重试。

## 8. 外部服务和本地依赖

### 8.1 Qwen 兼容 API

后端使用 OpenAI 兼容的 Chat Completions、Embeddings 接口：

- 知识结构生成：`ECHO_LLM_*`
- 聊天回答：`ECHO_CHAT_*`
- 向量化：`ECHO_EMBEDDING_*`

API Key 不写入前端，只保存在后端环境变量或 `.env`。Provider 调用失败时转换为 `502` 或 SSE `error`。

### 8.2 PDF 存储

- 当前使用 `LocalDocumentStorage`。
- 文件路径由 `Document.storage_key` 映射。
- `path_for()` 会阻止路径逃逸到配置根目录之外。
- 上传和解析是请求内同步流程，不依赖后台任务队列。

### 8.3 数据库

- 生产目标：PostgreSQL + pgvector。
- 测试：SQLite + aiosqlite，内存模式或临时文件数据库。
- pgvector 负责向量距离查询；SQLite 使用 Python 端 cosine 计算作为开发替代。

## 9. 当前边界

当前后端仍处于开发阶段，主要边界如下：

1. HTTP 运行时认证仍只有开发身份头；正式 Bearer 登录、刷新和登出 API 尚未接入。
2. PDF 解析、切块、Embedding 和 LLM 生成都在请求进程内执行，没有后台队列和任务重试。
3. 本地 PDF 存储适合开发演示，生产部署需要替换为对象存储。
4. 模型能力取决于 API Key、模型名称、上下文窗口和网络。
5. 数据库迁移需要显式执行，应用启动不会自动升级数据库。
6. 知识结构编辑的并发策略尚未统一到所有写路径。
7. 演示种子脚本已按课程隔离数据并使用确定性 ID；不同课程仍会复用同一批演示邮箱账号。

## 11. 一句话总结

后端以 FastAPI 为入口、SQLAlchemy Async 为持久化边界、Service 层为业务编排中心，围绕“课程教材 -> 解析切块 -> 向量检索 -> RAG 对话 -> 学习事件 -> 掌握度与审核 -> 教师分析”的主链路运行；所有模型调用和文件处理目前都在请求进程内完成，生产化前需要补齐正式认证、任务队列和对象存储。
