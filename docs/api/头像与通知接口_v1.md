# 头像与通知接口 v1

## 头像

### 上传当前用户头像

```http
POST /api/v1/auth/me/avatar
Content-Type: multipart/form-data
X-User-Id: <user-id>
```

字段：

```text
file: JPEG、PNG 或 WebP，最大 2 MB
```

后端校验文件签名，不信任文件名和客户端 MIME。成功后返回：

```json
{
  "avatar_url": "/api/v1/users/<user-id>/avatar?v=<version>"
}
```

### 删除当前用户头像

```http
DELETE /api/v1/auth/me/avatar
X-User-Id: <user-id>
```

成功返回 `204`。删除是幂等的，没有头像时也返回成功。

### 访问头像

```http
GET /api/v1/users/{user_id}/avatar
```

该地址只返回头像图片，使用用户 UUID 定位，不暴露文件系统路径。由于浏览器 `<img>` 无法携带 `X-User-Id`，此接口在开发认证下不要求认证头。URL 带 `?v=` 内容版本，可安全设置长缓存。

### Profile 响应

```http
GET /api/v1/auth/me/profile
GET /api/v1/auth/me
```

两者都返回 `avatar_url`。课程成员接口 `GET /api/v1/courses/{course_id}/members` 也返回每位成员的 `avatar_url`。

## 通知

### 列表与游标分页

```http
GET /api/v1/notifications?unread=true&cursor=&limit=20
X-User-Id: <user-id>
```

返回：

```json
{
  "items": [
    {
      "id": "uuid",
      "type": "ai_high_risk",
      "severity": "critical",
      "title": "AI 回答需要高风险审核",
      "body": "问题摘要",
      "action_url": "/review-flags/uuid",
      "payload_json": {
        "review_flag_id": "uuid"
      },
      "course_id": "uuid",
      "actor_id": "uuid",
      "read_at": null,
      "created_at": "2026-09-19T08:00:00+00:00"
    }
  ],
  "total": 1,
  "nextCursor": null,
  "unreadCount": 1
}
```

`limit` 范围为 1 到 100。`total` 是当前 `unread` 筛选下的总数，不受游标影响。

### 未读数

```http
GET /api/v1/notifications/unread-count
X-User-Id: <user-id>
```

```json
{
  "unreadCount": 3
}
```

### 标记单条已读

```http
POST /api/v1/notifications/{notification_id}/read
X-User-Id: <user-id>
```

只能读取自己的通知。其他用户的通知返回 `404`，避免泄露记录是否存在。

### 全部已读

```http
POST /api/v1/notifications/read-all
X-User-Id: <user-id>
```

```json
{
  "updated": 3,
  "unreadCount": 0
}
```

## 通知类型

```text
ai_high_risk
student_abnormal
course_member_change
system_status
```

当前已接入：

- 高风险 AI 审核标记创建时，向课程教师发送 `ai_high_risk` 通知。
- 学生通过课程码加入课程时，向课程教师发送 `course_member_change` 通知。

`student_abnormal` 和 `system_status` 已由模型、Schema、API Client 和枚举支持，供后续学习异常与系统监控流程接入。实时推送不在本轮范围内，后续可使用 SSE 或 WebSocket 复用同一通知模型。

## 数据库

- `users.avatar_storage_key`：仅用于服务端定位头像文件。
- `notifications`：按用户持久化通知、已读时间和去重键。
- 头像文件写入独立 `tmp/avatars` 根目录，不写入数据库 BLOB。
- API Key、密码和 `.env` 内容不会进入通知、头像响应或日志。
