# 教学策略与执行计划接口需求 v1

本文档定义教师端“教学策略 → 执行计划 → LearningEvent → 效果评估”闭环所需的真实后端契约。前端不会在接口缺失时自行模拟策略、计划、任务或效果。

## 目标闭环

```text
AI 教学洞察
→ 生成/查看教学策略
→ 教师采纳策略
→ 创建执行计划
→ AI 生成周计划草案
→ 教师修改并发布
→ 执行计划详情
→ 任务与 LearningEvent
→ 效果评估
→ 返回策略效果
```

## 通用约定

- 前缀：`/api/v1`
- 鉴权：沿用教师 `X-User-Id` 和课程成员权限校验。
- 分页：统一的 `items`、`total`、`nextCursor`。
- 时间：ISO 8601。
- 状态、类型和优先级必须由后端枚举约束；前端不自行创建无法持久化的值。
- AI 生成结果必须带 `source` 或 `generated_context`，让教师能区分 AI 草案和教师确认内容。

## Teaching Strategy

### 列表与生成

```text
GET  /api/v1/courses/{course_id}/teaching-strategies?status=&type=&priority=&cursor=&limit=20
POST /api/v1/courses/{course_id}/teaching-strategies/generate
POST /api/v1/courses/{course_id}/teaching-strategies
```

生成请求：

```json
{
  "knowledgePointIds": ["uuid"],
  "studentIds": ["uuid"],
  "insightIds": ["string"],
  "timeRangeDays": 28
}
```

```json
{

}
```

### AI 生成周计划

```text
POST /api/v1/execution-plans/{plan_id}/generate-weekly-plan
```

请求：

```json
{
  "teacher_note": "string",
  "regenerate": false
}
```

响应必须标记草案：

```json
{
  "status": "draft",
  "generation_id": "uuid",
  "weeks": [
    {
      "week_number": 1,
      "start_date": "2026-09-20",
      "end_date": "2026-09-26",
      "content": "string",
      "knowledge_point_ids": ["uuid"],
      "resource_ids": ["uuid"],
      "tasks": []
    }
  ],
  "recommendations": [
    { "id": "uuid", "content": "string", "status": "pending" }
  ]
```

生成失败时返回明确错误，前端保留教师已填写内容。

### 计划 LearningEvent

```text
GET /api/v1/execution-plans/{plan_id}/learning-events?studentId=&taskId=&knowledgePointId=&eventType=&cursor=&limit=50
```

复用现有 `LearningEventRecord`，并至少增加以下关联字段：

```json
{
  "plan_id": "uuid",
  "task_id": "uuid",
  "week_number": 1,
  "student": { "id": "uuid", "display_name": "string" },
  "knowledge_point": { "id": "uuid", "name": "string" },
  "result": "correct | wrong | completed | unresolved"
}
```

禁止另建前端事件模型；后端需提供计划/任务关联，或提供基于关联表的查询。

### 效果评估

```text
GET /api/v1/execution-plans/{plan_id}/effect
GET /api/v1/teaching-strategies/{strategy_id}/effect
```

响应结构：

```json
{
  "plan_id": "uuid",
  "strategy_id": "uuid",
  "period": { "start": "ISO-8601", "end": "ISO-8601" },
  "metrics": [
    {
      "metric": "mastery_change",
      "label": "目标学生平均掌握度",
      "before": 49,
      "after": 62,
      "delta": 13,
      "sample_size": 10,
      "source": "mastery_snapshot"
    }
  ],
  "task_effectiveness": [
    {
      "task_id": "uuid",
      "title": "string",
      "completion_rate": 0.83,
      "event_count": 24,
      "observed_change": 8
    }
  ],
  "remaining_issues": ["string"],
  "facts": ["string"],
  "ai_explanation": "string | null",
  "insufficient_evidence": false
}
```

效果字段只描述观察到的变化，不能返回“计划导致 X% 提升”的因果断言。没有足够证据时 `insufficient_evidence=true`。

## 后端验收

- 所有策略、计划和任务状态可持续化并可恢复。
- AI 生成物初始状态必须是 `suggested` 或 `draft`，未经教师动作不能变为 `accepted`、`active` 或 `completed`。
- `/execution-plans/{plan_id}/learning-events` 返回真实 LearningEvent，且可以回溯学生、任务、知识点和计划。
- 效果评估可以区分事实变化、AI 解释和证据不足。
- 暂停/恢复/完成计划不能删除历史任务或 LearningEvent。
- OpenAPI 必须包含上述路径，并同步 `shared-types`、`api-client`。

## 前端接入顺序

1. 教学策略列表与详情。
2. 策略采纳、进入创建计划。
3. 五步执行计划向导。
4. 发布并进入计划详情。
5. 周计划、任务、LearningEvent。
6. 效果评估和策略效果回流。
